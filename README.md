# Remna Agent

Веб-панель для управления нодами Remnawave: список серверов, SSH-учётные данные, статус Online по ping.

> v0.1 — список нод (CRUD), копирование IP/паролей/ключей, Online-пинг. Установка/переустановка агента на ноде — в следующих версиях.

## Возможности

- Авторизация админа из `.env` (`ADMIN_USERNAME` / `ADMIN_PASSWORD`)
- PostgreSQL: ноды (имя, host, SSH, пароль или ключ в зашифрованном виде)
- Тёмный UI в духе панели Remnawave
- Копирование host и секретов одной кнопкой
- Колонка **Online**: проверка доступности каждые 5 секунд (ICMP, fallback TCP на SSH-порт), без перерисовки всего списка
- Загрузка приватного ключа из файла, включая PuTTY **`.ppk`** (конвертация в OpenSSH на сервере)
- Кнопка **Проверить SSH** в карточке ноды → статус `SSH-OK` / `fail` (текст ошибки во всплывающей подсказке)
- Справочник **Хостинги** (CRUD), URL сайта, переход из списка; favicon как логотип (иначе буква названия)
- Выбор/добавление хостинга в карточке ноды
- Нижняя статус-полоска: сколько нод Online и сколько не на связи
- Лёгкий **агент на ноде** (CPU/RAM/Disk): кнопка установки по SSH, статус и метрики в списке (порт `7422`)

## Требования

- Docker и Docker Compose
- Свободные порты `8080` (web) и `8000` (api, опционально)

## Быстрый старт

```bash
git clone https://github.com/BobJustFry/remna-agent.git
cd remna-agent
cp .env.example .env
```

Отредактируйте `.env`: задайте свой пароль админа и секреты сессии/шифрования.

```bash
docker compose up -d --build
```

Откройте панель: [http://localhost:8080](http://localhost:8080)

Логин по умолчанию из `.env.example`: `admin` / `change-me`.

Остановка (данные **сохраняются**):

```bash
docker compose down
```

## Автоматизация

Раздел с проверками состояния парка. Все проверки **только читают** панель
Remnawave и сеть — ничего не меняют ни в панели, ни на нодах.

**Фонового расписания намеренно нет.** Проверки выполняются только по кнопке из
интерфейса. Когда понадобится расписание, достаточно повесить периодический вызов
на `audit.run(check_id)` — сами проверки при этом не меняются.

| Проверка | Что смотрит | Из-за чего появилась |
|---|---|---|
| CDN-фронты живы | резолвятся ли техдомены CDN; не уехал ли запинённый эдж из пула | аккаунт CDN заблокировали, техдомен пропал из DNS, хост сутки отдавал клиентам 403 |
| Сроки сертификатов | сколько осталось у клиентских сертификатов и у доменов из списка | сертификат подписки на CDN продлевается вручную, пропуск срока кладёт выдачу подписок всем |
| Расхождения в панели | забытый Host у xhttp, SNI хоста поверх профиля, хосты без ноды, инбаунды-сироты, повторяющиеся dest | после смены dest у части хостов остался прежний Host, а явный SNI хоста перекрыл профиль |
| Транспорты хостов | какие включённые хосты остались на RAW и идут ли напрямую | на части сетей RAW душится DPI: туннель встаёт, трафика нет |

Домены для проверки сертификата, которых нет в панели (например домен подписки),
задаются в самом разделе и лежат в `app_settings` обычным JSON — это не секрет.

Что проверки сознательно **не** считают поломкой: выключенные хосты, хосты-баннеры
на публичных резолверах (`1.1.1.1:1234` и подобные), REALITY-хосты в проверке
сертификатов (там чужой сертификат сайта-прикрытия) и Hysteria (UDP, по TCP
сертификат не прочитать). Недоступность узла по TCP помечается как сведение, а не
тревога: она зависит от того, откуда смотрит агент.

## Сохранность данных БД

PostgreSQL пишет в каталог проекта [`data/postgres`](data/postgres) (bind mount).  
Пересборка (`--build`), `docker compose down`, перезапуск контейнеров — данные **не** удаляют.

Что реально стирает базу:

- удаление папки `data/postgres`
- `docker compose down -v` (если где-то снова появятся named volumes)
- смена `CREDENTIALS_ENCRYPTION_KEY` — строки в БД останутся, но пароли/SSH-ключи нод перестанут расшифровываться

Бэкап:

```bash
# Windows
powershell -File scripts/backup-db.ps1

# Linux/macOS
sh scripts/backup-db.sh
```

Копии: `data/backups/`.

## Переменные окружения

| Переменная | Описание |
|---|---|
| `ADMIN_USERNAME` | Логин в веб-интерфейс |
| `ADMIN_PASSWORD` | Пароль |
| `SESSION_SECRET` | Секрет подписи cookie-сессии |
| `CREDENTIALS_ENCRYPTION_KEY` | Ключ AES для паролей/SSH-ключей (рекомендуется 64 hex-символа = 32 байта) |
| `DATABASE_URL` | Строка подключения PostgreSQL (asyncpg) |
| `WEB_PORT` | Порт UI на хосте (по умолчанию `8080`) |
| `API_PORT` | Порт API на хосте (по умолчанию `8000`) |
| `ENVIRONMENT` | `development` или `production` |
| `COOKIE_SECURE` | `true` на HTTPS (в production включается само) |
| `OPENAPI_URL` | Пустая строка отключает `/docs` ([Conditional OpenAPI](https://fastapi.tiangolo.com/how-to/conditional-openapi/)) |
| `ALLOWED_HOSTS` | Хост для TrustedHost; в production конкретный домен |
| `CORS_ORIGINS` | Список Origin через запятую |
| `TRUST_PROXY` | Доверять `X-Forwarded-*` (Caddy/nginx) |
| `AGENT_RU_PING_TARGETS` | Цели пинга «до России» с нод через запятую (по умолчанию якоря RIPE Atlas в Москве `185.32.187.161,81.27.254.54`); уходит в env агента при (пере)установке |
| `RETR_MIN_DATA_SEGS_5MIN` | Порог объёма для доли TCP-ретрансмитов: сегментов с данными (`TCPOrigDataSent`) за 5 минут, по умолчанию `20000`; для других шагов пересчитывается пропорционально времени. Ниже порога доля помечается «мало трафика» и не красится |

## API-токены

Для скриптов и интеграций — не логин/пароль, а персональный токен. Выпускается
в **Настройки → API-токены**, показывается один раз; в базе лежит только SHA-256.

```
Authorization: Bearer rga_…
```

Токен даёт те же права, что сессия админа, на всё API, кроме управления
самими токенами — выпуск и отзыв работают только из браузерной сессии.
Отзыв действует мгновенно, `last_used_at` в списке обновляется не чаще раза
в минуту.

## Следилка за подпиской

Забирает подписку так же, как её забирает клиент, и считает конфиги внутри, а
не смотрит на код ответа: самая подлая форма этой аварии отвечает `200` с
пустым телом. Когда путь через CDN не отвечает, дополнительно щупается ориджин
напрямую — по этому и видно, чья поломка.

Почему отдельно от прочих проверок: всё остальное в парке заявляет о себе само
(мёртвая нода уходит в offline, сломанный хост теряет пользователей), а
переставшая отдаваться подписка молчит — уже подключённые продолжают работать
на скачанном конфиге, и единственный симптом это «новые не могут подключиться»,
который приезжает обращением через несколько дней.

Результат виден сразу в трёх местах: несъёмная полоса поверх приложения,
значок в статусной строке и карточка на дашборде. В Telegram уходит сообщение
на каждом переломе (упало / поднялось), пока лежит — напоминание раз в час.

Настраивается в «Настройках»: ссылка на подписку, та же ссылка мимо CDN,
интервал, минимальное число конфигов, токен бота и id чата. Токен бота лежит
зашифрованным и обратно не показывается. Пока переключатель выключен, фоновая
задача просто спит.

## Следилка за нодами

Хостер может приостановить ВПС на сутки, и видно это только по нулю в счётчике
пользователей. Сэмплер метрик и так опрашивает агент на каждой ноде раз в
полминуты — следилка считает, сколько нода уже не отвечает, и пишет в Telegram,
когда молчание перевалило за порог (по умолчанию 10 минут), а потом ещё раз,
когда нода поднялась: сколько лежала и с какого времени.

Чтобы чат не превратился в шум:

- пропущенный опрос тревогой не считается — только непрерывное молчание дольше порога;
- ноды, упавшие вместе, идут одним сообщением; о лежащих напоминает не чаще
  раза в N часов (по умолчанию 6, `0` — не напоминать);
- разом замолчало больше половины нод — это, скорее всего, ослеп сам рагент:
  одно сообщение про парк с разбивкой по хостерам, а не по сообщению на ноду;
- тревоги лежат в базе (`node_outages`), поэтому перезапуск рагента не повторяет
  их и не выдумывает восстановлений, а первый опрос после старта отказом не считается;
- ноды из списка исключений и ноды, выключенные в панели Remnawave, не тревожат;
- рагент до ноды не дотягивается (ни агент, ни SSH), а панель видит её
  подключённой — нода жива: рагент стоит в России, и до части зарубежных
  адресов ему просто не достать. Тревоги нет, у ноды серая пометка «рагент не
  достаёт, панель видит», а сигналом жизни для неё становится панель: потеряла
  ноду и панель — обычная тревога, вернулась в панель — восстановление. Пока
  панель сама не отвечает, по таким нодам не гадаем; молчит дольше порога —
  одно сообщение «рагент не видит панель». Отключается галкой в настройках.

В сообщении — имя, адрес, хостер, время и что именно молчит: агент, SSH-порт
(в него стучимся, только когда не ответил агент) и видит ли ноду панель. Если
SSH открывается, сервер жив и молчит только агент — про это отдельный текст.

Настраивается в «Настройках» (порог, напоминания, чат, исключения, часовой пояс
сообщений); бот — тот же, что у следилки за подпиской. Пометка «недоступна с
ЧЧ:ММ» стоит у ноды на дашборде и в списке нод, журнал простоев — в
«Автоматизации».

## Доступность приложений

Значки 🧠 и 📱 в имени хоста обещают клиенту, что через хост открываются
нейросети и TikTok. Ломается это молча (пропал WARP на ноде, сменилась точка
выхода, TikTok пометил адрес), поэтому раздел «Доступность приложений»
проверяет каждый хост подписки сам — по умолчанию раз в 12 часов.

Через каждый хост поднимается отдельный клиент xray, запросы идут с отпечатком
Chrome (`curl_cffi`), на сервис — один лёгкий запрос, до трёх попыток, пока не
получится определённый ответ. Вердикт — по признакам, а не по коду ответа:
«работает / отказ / челлендж / таймаут / ошибка».

| Группа | Сервис | Что проверяем |
|---|---|---|
| ИИ | ChatGPT, OpenAI API, Claude, Anthropic API, Gemini, Gemini API (если задан ключ) | страница или ответ API без ключа; отказ по стране — по редиректу, JSON-ошибке, маркерам |
| Приложения | TikTok | `GET https://www.tiktok.com/login`: отдал страницу входа — работает; заслонка WAF (~1,5 КБ, «Please wait…», `slardar_us_waf`), увод со страницы входа или регион RU — отказ. Заголовок `Server: TLB` ничего не решает |

Можно проверить весь парк, отмеченные хосты или один; идущую проверку можно
отменить. Матрица показывает последний результат каждого хоста и подсвечивает,
что изменилось. В Telegram уходит сводка после полного прогона, только если
что-то сломалось или починилось (ok ↔ отказ/челлендж) или сменилась страна
выхода ИИ; таймауты не шлём.

URL страницы (`/ai-access`), API (`/api/ai-access/...`) и таблицы
(`ai_runs`, `ai_checks`) называются по-старому — так не ломаются скрипты и
история. Результаты хранятся JSON-ом по ключам сервисов, поэтому новое
приложение не требует миграции: у старых прогонов его колонка просто пустая.

## Шаринг

Раз в две минуты рагент спрашивает у панели, с каких адресов сейчас заходит
каждый пользователь (`GetStatsOnlineIpList` ядра Xray), и выносит оценку от 0
до 100. Жёсткого порога «восемь адресов за пять минут» больше нет: он одинаково
судил подписку на одно устройство и семейную на пять.

**Норма считается от лимита устройств человека** (`hwidDeviceLimit`; пусто —
общий лимит из панели, `0` — оплаченный безлимит): норма = лимит × «на
устройство» + запас. Признак даёт свой вес целиком, когда значение вдвое
превысило норму, и ноль, пока оно в норме, — поэтому красит не один выброс, а
совпадение нескольких признаков.

| Вес | Признак | Почему столько |
|---|---|---|
| 24 | одновременно живых адресов | пачка адресов в одну минуту; роуминг по вышкам даёт их последовательно |
| 24 | одновременно живых операторов | разные сети в одну минуту — это уже не «переехал с Wi-Fi на LTE» |
| 14 | одновременно активных платформ | iOS+Android+Windows при лимите 1 — это трое разных людей |
| 9 | невозможное перемещение | **признак слабый:** страна берётся из регистрации сети (Team Cymru), не из геобазы |
| 9 | одновременных HWID сверх лимита | переустановки идут друг за другом, живые устройства — вместе |
| 8 | уникальных адресов за 5 мин | мобильный абонент меняет адрес сам по себе |
| 5 | нет ночной паузы | у человека в сутках есть провал на сон, у раздачи на компанию его нет |
| 4 | уникальных адресов за 15 мин | то же, но окно шире |
| 3 | трафик против медианы парка | сам по себе ничего не доказывает |

Красная зона — от 60 баллов, жёлтая — от 35. **Тревога уходит в Телеграм только
когда красная зона держится три проверки подряд** (шесть минут): переезд с Wi-Fi
на LTE, гость с телефоном и дача на выходных дают один красный скан и проходят.
Пока человек в красной зоне, напоминание раз в сутки; три зелёных скана подряд
снимают тревогу. Бот — тот же, что у следилки за подпиской.

Ночная пауза требует истории, поэтому рагент копит часовой профиль присутствия
в таблице `sharing_activity` (две недели, чистится сам). Признак молчит, пока
наблюдений меньше трёх суток. Онлайном для профиля считается только свежая
метка: панель держит человека в списке и через сутки после последнего пакета.

HWID и платформы стоят запроса на человека, поэтому за скан спрашивается не
больше 60: сначала те, кто уже набрал половину жёлтой зоны, остальное место —
всем по кругу, так каждый проверяется примерно раз в десять минут.

Список подозрительных с расшифровкой «за что» и ссылкой на досье — в разделе
**Шаринг**; у ноды остаётся прежний значок `SHARED`, он загорается только на
красной зоне. Все пороги и веса лежат в `app_settings` и правятся там же, из
браузера.

Чего рагент не делает: **лимиты устройств не меняет никому и ни при каких
условиях** — это платная услуга владельца, и решение всегда за человеком. В
панель и на ноды ходит только читать.

## Production (HTTPS)

[Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https) берёт сертификат Let's Encrypt, если A-запись домена смотрит на VPS и открыты 80/443:

```bash
cp .env.example .env
# сильные ADMIN_PASSWORD, SESSION_SECRET, CREDENTIALS_ENCRYPTION_KEY, POSTGRES_PASSWORD
# CORS_ORIGINS=https://your.domain
# ALLOWED_HOSTS=your.domain
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

API (`8000`) и Postgres наружу не публикуются. Пароль админа не должен совпадать с root SSH.

Если на VPS уже есть Caddy на 80/443 (как geodat.bob4.fun), **не** поднимайте второй Caddy: оверлей подключает `web` к сети `bob4fun-geodat-editor_default`, а в существующий Caddyfile добавляется сайт `ragent.bob4.fun` → `remna-agent-web:80`.

## Примечания по Online

- Запрос `GET /api/nodes/online` пингует все ноды параллельно
- Предпочтительно ICMP; если ICMP недоступен — TCP connect к `ssh_port`
- Для ICMP контейнеру `api` выданы capabilities `NET_RAW` / `NET_ADMIN`

Docker Desktop на Windows ходит в интернет через таблицу маршрутов хоста.
Если поднят **VupenVPN** (Wintun, `198.18.0.0/15` + широкие префиксы), ICMP
к большинству нод отвечает сам TUN (~0–2 мс, TTL 64) — это не пинг до VPS.
Часть адресов (как `de-1`) уже уходит в Ethernet по /32 — отсюда «то через
туннель, то через VPN».

Обход: host-маршруты всех IP нод в LAN-шлюз (нужен Administrator):

```powershell
powershell -File scripts/windows/sync-direct-routes.ps1
```

Повторить после реконнекта Vupen, если /32 пропали. Снять: `-Remove`.
